# v8 plan: one home for everything pic writes

Working plan for `container-bootstrap-8`. Delete this file when the branch
merges; the result lives in `pi-container/docs/configuration.md`.

## Goal

Everything pi-container and fleetd write on the Mac lives under one root,
`~/.pic`, overridable with `PIC_HOME`. Backwards compatibility is a one-time
migration, not a permanent fallback (0.1.0 is the only release).

## Paths

| Today (v7) | v8 |
|---|---|
| `~/.config/pi-container/` (default profile) | `$PIC_HOME/config/` |
| `~/.config/pi-container/private/host-setup.lock` | `~/.pic/lock` (see decision 4) |
| other profiles: any `PI_CONFIG_DIR` | unchanged; docs suggest `$PIC_HOME/profiles/<name>` |
| `~/pi-backups/` | `$PIC_HOME/backups/` |
| `~/.fleet/` | `$PIC_HOME/fleet/` |
| `~/.config/pi-container-e2e-test` (mac-e2e.sh) | `$PIC_HOME/profiles/e2e-test` |
| `~/.cache/pi-e2e/` (logs, scratch) | unchanged: disposable |
| `~/.local/share/local-model/` | unchanged: shared model weights |
| `~/.cache/huggingface/token` | unchanged: read only |

`PI_CONFIG_DIR`, `PI_ENV_FILE` and `PI_BACKUP_DIR` keep working and beat the
derived paths.

## Behavior

- **Refuse legacy paths.** `run.sh`, `clear.sh` and `pic serve` exit 2 while
  `~/.config/pi-container`, `~/pi-backups` or `~/.fleet` exists and is not
  named in `overrides.env`, printing `pic migrate`. Same pattern as the
  v7 `config.json` refusal.
- **`pic migrate`** (`pi-container/migrate.sh`):
  1. Exits early if `$PIC_HOME` exists. `PIC_HOME=/elsewhere pic migrate`
     targets another root.
  2. Refuses while `pic serve`, a pi-proxy or a pi container is running.
  3. For each legacy path, prompts with the detected path as the default:
     move it into `$PIC_HOME`, or keep it where it is.
  4. Moves with `mv` (same volume, so secrets are never copied); refuses a
     cross-device move.
  5. Writes `$PIC_HOME/overrides.env` (mode 600) for every kept path, e.g.
     ```sh
     # pic overrides v1, written 2026-11-27T06:40:00Z by pic migrate (0.1.0 -> 0.2.0)
     PI_BACKUP_DIR=/Users/tan/pi-backups
     ```
  6. Prints `clear.sh list` so you can check every volume still has a profile.
- **Volumes survive.** The default profile has no id, so its volume, proxy
  and network names don't change when its directory moves. `clear.sh list`
  must stop showing them `(missing)` because their `pi.config` label still
  names the old path. Non-default profiles are not moved: their names hash
  their path.
- **fleetd** reads `PIC_HOME` and stores data in `$PIC_HOME/fleet`. It passes
  `PIC_HOME` to `pi-ctr`, and `run.sh --fleet-state` checks against
  `$PIC_HOME/fleet/sessions`. Session logs hold no absolute paths, so moving
  the folder is safe while `pic serve` is stopped.

## Work

1. `names.sh`: `pi_pic_home`, then derive the default profile, backups, fleet
   and lock from it. Unit tests in `test-paths.sh`.
2. The legacy-path refusal in `run.sh`, `clear.sh` and `serve.sh`, with
   integration cases.
3. `migrate.sh` plus integration cases: early exit, move, keep with an
   override, a running proxy, cross-device, rerun.
4. `overrides.env` reader in `lib/config.sh`: path keys only, version `v1`
   only; refuse anything else.
5. fleetd and `pi-ctr`: `PIC_HOME`, Go tests, `fleet/e2e/pi-ctr.sh`.
6. `mac-e2e.sh`: profile under `$PIC_HOME/profiles/`, and a migrate phase on
   a fake legacy layout.
7. Docs: configuration.md path table, README, operations.md (backups,
   removal), manual.md (Neovim paths), fleet/README and macos.md (`~/.fleet`),
   playbooks.md, E2E.md, AGENTS.md.
8. Mac: `pic migrate` on your real layout, then E2E.md and fleet step 8.

## Open decisions

1. **Default profile folder.** `$PIC_HOME/config` (recommended: keeps the
   profile separate from machine-wide backups and fleet data), or `$PIC_HOME`
   itself.
2. **Is `overrides.env` read at runtime?** Recommended: yes, path keys only
   (`PI_CONFIG_DIR`, `PI_ENV_FILE`, `PI_BACKUP_DIR`), with env vars beating it.
   Not read, it's only a record, and you'd export the vars yourself. Either
   way, run settings (`PI_IMAGE` etc.) stay env-only.
3. **Interactive prompts.** `migrate.sh` prompts; `run.sh` only prints the
   command, because fleet turns and scripts have no terminal. Alternative:
   `run.sh` offers to run the migration when stdin is a TTY.
4. **The lock across roots.** Images and the builder cache are machine-wide,
   so the lock must be too. With `PIC_HOME` it can't live under `$PIC_HOME`.
   Recommended: always `~/.pic/lock`.
5. **Non-default profiles.** Recommended: never moved (their names hash the
   path). Alternative: move and reap their volumes, after `clear.sh save`.
6. **Version.** Tag v8 as `0.2.0`, and stamp that in `overrides.env`.
